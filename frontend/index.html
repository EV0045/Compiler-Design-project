What this tests

    

      
For each kernel the regression suite generates random inputs and runs both the baseline (leaky) and transformed (constant-time) implementations on the same inputs. If any output differs, the transformation is considered incorrect.

      
All three kernels pass with 0 mismatches, confirming the transformations are semantics-preserving.

Interpretation

    

      
aes_sbox and mod_exp incur ≤3% overhead — the constant-time versions are nearly as fast as the originals.

      
memcmp shows ~17% overhead because it must scan all n bytes unconditionally instead of returning early; this is the correct behaviour — the early-exit is exactly the timing leak being removed.

    

  








  

    
Project overview

    

      
This project implements an LLVM pass that detects and eliminates secret-dependent control flow — a class of timing side-channel vulnerability where a program's execution time reveals information about secret data.


      
The threat model

      
Consider a password comparison that returns early the moment it finds a mismatch. An attacker who can measure response time can binary-search the correct password one byte at a time. The same issue applies to AES S-Box table lookups and modular exponentiation with secret exponents.


      
What the pass does (3 phases)

      
    
        
  1. Taint labelling — parameters marked secret in a JSON config are propagated through the CFG using a dataflow analysis. Any value that depends on a secret is tainted.
    2. 
        
  2. Violation detection — branch instructions (br) and function returns whose condition is tainted are flagged as constant-time violations.
    3. 
        
  3. Transformation — secret-dependent branches are replaced with LLVM select instructions (branchless CMOVs), eliminating the timing-observable control-flow differences.

Verification

      
On Linux/Ubuntu the transformed binaries are verified with ctgrind (Valgrind Memcheck taint tracking): secret-tainted bytes are poisoned and any branch on a poisoned value triggers a Valgrind error. The transformed aes_sbox passes with 0 errors.
