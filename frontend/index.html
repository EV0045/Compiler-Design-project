Verification Methodology

    

      
For each kernel, the automated regression harness generates extensive test vectors across edge cases (all zeros, all ones, random bit distributions, and alternating patterns). Both the original and transformed versions are executed on identical inputs.

      
All three target kernels pass with exactly 0 mismatches across 4,268 cases, confirming 100% semantic correctness.

Performance Analysis

    

      
aes_sbox and mod_exp demonstrate minimal overhead (≤3.2%), proving that branchless IR multiplexing achieves constant-time security without unacceptable CPU slowdown.

      
memcmp exhibits ~17% overhead because the constant-time algorithm is mathematically required to inspect every single byte rather than early-exiting on the first mismatch. This overhead is the intentional cost of eliminating the timing channel.

    

  








  

    
Compiler Pipeline Architecture

    

      
This project implements an LLVM plugin pass registered as constant-time-pass that operates over the Control-Flow Graph (CFG) in LLVM Intermediate Representation (IR).


      
Four-Module Architecture

      
    
        
  1. Module 1 (Secrecy Labeller): Ingests JSON policy and marks sensitive function parameters as SECRET.
    2. 
        
  2. Module 2 (Taint Engine): Forward iterative fixed-point dataflow analysis over the CFG propagating taint through PHI nodes, GEPs, arithmetic, and memory operations.
    3. 
        
  3. Module 3 (Violation Detector): Identifies secret-dependent branches (BRANCH_LEAK) and secret memory accesses (MEMORY_LEAK). Also acts as the post-pass verifier (verifyZeroLeaks).
    4. 
        
  4. Module 4 (Constant-Time Transformer): Rewrites secret branches to select (hardware CMOVs) and constant array lookups to uniform bitmask linear scans.
    5. 
      


      
Hardware Timing Guarantees

      
Transformed kernels are tested with ctgrind (Valgrind Memcheck with taint tracking). Secret memory is marked poisoned; any CPU instruction whose branch condition or memory address depends on poisoned bytes immediately raises a violation. Transformed code completes with 0 errors.
